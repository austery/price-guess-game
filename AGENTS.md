# AGENTS.md

Live "closest without going over" price-guessing game for a company holiday event (up to 20 tables, one phone per table, a host screen). Runs on Cloudflare Workers + one Durable Object. `README.md` (Chinese) covers usage and config editing; `docs/spec.md` has the rules. This file covers what you need before changing code.

## Commands

```bash
npm install
cp .dev.vars.example .dev.vars   # local host key: dev-host-key
npm run dev                      # wrangler dev on http://127.0.0.1:8787; host page: /host?key=dev-host-key
npm run typecheck                # tsc --noEmit (covers src/ only, not public/ or scripts/)
npm test                         # vitest run (unit tests, fake clock, no Workers runtime)
npx vitest run test/scoring.test.ts          # one file
npx vitest run -t "tie"                      # by test name
npm run simulate                 # needs `npm run dev` running; 20 phones + host play a full game
npm run deploy                   # then: npx wrangler secret put HOST_KEY
```

- `simulate` resets the game state of the server it hits. Never point it at the live event URL.
- CI (`.github/workflows/ci.yml`) runs typecheck, tests, then starts `wrangler dev` and runs `simulate`. Run all three before pushing.
- `worker-configuration.d.ts` is generated by `npm run types`. Do not edit it by hand.

## Architecture

Three layers. The rule that matters most: **the server holds all state and all true prices; browsers only get views.**

1. `src/worker.ts` — entry Worker. Serves `/ws` (checks role and host key, then forwards to the Durable Object), `/api/host-check`, and `/qr.svg`. Static pages come from `public/` through the `assets` binding. It strips the host key before forwarding to the room.
2. `src/room.ts` — `GameRoom` Durable Object, a single instance (`idFromName("main")`). It owns persistence (`storage.put("state")`), the deadline alarm, and WebSocket fan-out with the Hibernation API. It contains no game rules. Each message becomes one call into `game.ts`; if `state.version` changed, it persists, re-arms the alarm, and broadcasts a fresh view to every socket.
3. `src/game.ts` + `src/scoring.ts` — the game, as pure functions over a plain JSON `GameState`. No I/O, no clock reads (`now` and `rand` are passed in), so tests drive them with a fake clock.
   - Phases per round: `waiting → open → locked → revealed → … → final`. The header comment in `game.ts` is the source of truth for the intro, practice and tiebreak flows.
   - Round indexes: practice rounds use `practiceRound` and bid key `p0`, `p1`. Real rounds are `0..dishes.length-1`. Tiebreak rounds continue at `dishes.length + i`.
   - `scoring.ts` has price parsing (cents, integers) and the "closest without going over" scoring.
4. `public/` — plain HTML/JS, no framework, no build step. `host.html` is the big screen and controls; `index.html` is the player phone page; `common.js` is the shared WebSocket client (reconnect, `ping`/`pong`).

Content (`src/config.ts`): `CATALOG` (merged from `src/magazine.ts` plus hand-made `SLIDE_ITEMS`), `basket()` helper, and the `practice` / `dishes` / `tiebreakers` lists. Round count follows `dishes.length`. `src/magazine.ts` was generated from the PC Insiders Holiday 2026 magazine; the generator is not in this repo, so edit the file directly.

## Invariants — do not break

- **Prices never leave the server before reveal.** `playerView` and `hostView` are the only way state reaches a browser. `dishView()` in `game.ts` copies part fields one by one, because a `Dish` part carries `unitCents`. Never spread a dish or part object into a view. `result` is `null` until phase `revealed`. If you add a field to a view, check it against this rule and add a test.
- **`public/` is world-readable.** Never put prices there. Image filenames in `public/items/` must not be guessable and must not contain the price (use a random suffix, like `name-a5fbb5.jpg`). Check that the picture itself shows no price.
- **Money is integer cents** everywhere (`3075` = $30.75). Do not use floats for prices.
- **Late bids** are decided server-side against `deadline` (plus grace). The client countdown is display only. The alarm locks the round; `maybeLock` also runs on every message and on connect, to catch deadlines that passed while the object was hibernating.
- **`GameState` is persisted JSON.** When you add a field, give it a default in `initialState` and handle old saved state in `normalizeState`. A deployed room may hold state from an older version.
- Table count is `cfg.tables` (in `config.ts`). Host and phone pages lay out tables from it; check both pages when it changes.

## Conventions

- Code, comments, commits and docs in English. The README, `docs/spec.md` and `docs/session-summary.md` are in Chinese because the organizer reads them. Keep them in Chinese.
- Game logic changes go in `game.ts` / `scoring.ts` with a test in `test/`. Keep `room.ts` free of rules.
- `docs/session-log/` is an archive of past sessions. Do not delete or rewrite it.
- `docs/codex-task-basket-products.md` is a data-collection brief for another agent. It is not code documentation.
