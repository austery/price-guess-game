# 猜食材价格游戏 — 需求说明

> 状态：核心功能和加赛已实现，规则已全部确认。题目内容（公司产品）和界面细节待定。

## 游戏规则（来自活动原始说明）

- 5 道菜：1 道前菜、2 道主菜、2 道甜点。每道菜一页，列出 3～6 种主要食材。
- 每桌猜这道菜所有食材的**总价**。
- **最接近但不超过**真实价格的一桌赢得这一轮（The Price Is Right 规则）。
- 赢得轮数最多的一桌获得奖品。

## 现场形式

- 15 桌，**每桌一部手机**，扫码进入，不用装 App、不用注册。
- 大屏（投影/电视）显示二维码、菜品、倒计时、揭晓结果和排行榜。
- 主持人在大屏页面底部的控制栏操作（空格键 = 主按钮）。

## 每轮流程

```
等待 →[开始]→ 菜品出现 + 15 秒倒计时 →[时间到，服务器自动锁定]→ 锁定 →[揭晓]→ 显示结果 →[下一步]→ 排行榜 / 下一轮
```

- 菜品和倒计时**同时出现**：之前没人见过题目，无法提前查价。
- 截止时间由服务器判定（另有 0.75 秒网络宽限），改手机时间无效。
- 主持人可以提前结束本轮（所有桌都答完时），也可以重做本轮。
- **揭晓前，真实价格不会发送到任何手机或浏览器。**

## 计分

- 金额以"分"为单位存成整数（30.75 → 3075）。
- 输入支持 `30.75`、`$30.75`、`30,75`、`30`，最多两位小数。
- 报价 > 真实价格：本轮无效。有效报价中最高者得 1 分。
- 总排名按赢的轮数；同分者排名相同。

## 已确认的规则（均可在 `src/config.ts` 修改）

| # | 问题 | 决定 | 配置项 |
|---|---|---|---|
| 1 | 同一轮两桌报出相同的最高有效价 | 都得 1 分 | `rules.roundTie: "all-score"` |
| 2 | 某一轮所有桌都超价 | 本轮无人得分 | — |
| 3 | 15 秒内能否改价 | 可以，以最后一次为准 | `rules.allowResubmit` |
| 4 | 手机上显示什么 | 名称 + 说明文字，不显示图片 | `rules.phoneShowsImage` |
| 5 | 揭晓时是否公开每桌报价 | 全部公开，从高到低，超价标红 | `rules.revealAllBids` |
| 6 | 界面语言 | 英文 | — |
| 7 | 是否用 PPT | 不用，只用网页，排版由程序决定 | — |
| — | 倒计时 | 15 秒 | `roundSeconds` |
| — | 提示语（猜什么） | 可改，例如改成猜产品售价 | `guessPrompt` |

## 总冠军平局：加赛

5 轮后如果两桌或以上并列第一（15 桌水平相近时约一半的机会），主持人按空格开始**加赛**：

- 只有并列的桌参加，其他桌手机显示"观战"，不能作答。
- 1 道加赛题（`tiebreaker`），同样 15 秒。
- 判定顺序：
  1. 最接近但不超过者赢；
  2. 如果并列的桌全部超价 → 离真实价格最近者赢；
  3. 如果仍然无法分出（最高有效价相同、距离相同，或都没作答）→ 系统当场随机抽签。
- 没作答的桌算输。
- 加赛只决定冠军，不改变 5 轮的得分。加赛只进行一次，不会无限加下去。
- 建议另外准备一道后备题，以防加赛题临时出问题需要替换。

## 题目内容（待定）

- 题目是**公司在超市销售的产品**，不是菜。程序不限制题目类型：每题 = 名称 + 可选说明列表 + 图片 + 真实价格。
- 原规则要求猜"食材总价"，资料难以取得；可能改为直接猜产品售价，届时只需修改 `guessPrompt` 和题目内容。
- 图片优先用现成的产品宣传图（例如 flyer、官网图）。

## 异常处理

| 情况 | 处理 |
|---|---|
| 手机刷新 / 断线 / 锁屏后回来 | 自动重连，桌号和本轮报价都保留 |
| 手机没电，换一部手机 | 主持人在大屏上点击该桌号 → 释放 → 新手机重新选桌 |
| 两部手机抢同一个桌号 | 先到先得，后来的提示"已被占用" |
| 主持人页面刷新 | 游戏状态存在服务器上，不会丢 |
| 彩排结束后清场 | Reset game → 第二个确认框选 OK，所有桌需要重新选桌 |
| 现场网络差 | 程序无法解决：活动前必须在现场实测；准备纸卡作为后备 |

## 技术架构

- Cloudflare Workers（免费版）+ 一个 Durable Object 作为唯一的游戏房间。
- Durable Object 保存状态、用 alarm 执行截止锁定、通过 WebSocket 把状态推送给所有屏幕和手机（Hibernation API）。
- 前端：纯 HTML + JavaScript，无框架、无构建步骤。
- 主持人页面用密钥保护（服务器 secret `HOST_KEY`）。
